> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

Source of truth:

Goal:
- Consume Agent Browser Core package family `0.3.1`.
- Let ABC own MAP URI parsing, MAN protocol resolution, and generic Browser rendering.
- Let OAC own local actor selection, local conversation UI routing, safe host action hrefs, and profile/runtime security boundaries.

Non-negotiable boundaries:
- Do not trust `payload.href` or any remote-provided href for `open-conversation`.
- Do not allow a remote Bot Page or MAP URI to choose the local Bot; only the selected OAC Browser actor/profile determines `local`.
- Do not copy MAP URI parsing logic into OAC; call ABC APIs for parsing and MAP resource resolution.
- Do not add `@openagentinternet/agent-browser-host-standalone` to `dependencies`, `devDependencies`, package lock entries, or generated package artifacts.
- Do not expose local secrets, signers, wallet handles, or private profile state to ABC.
- Do not execute chain-declared renderers inside OAC. ABC may render declared protocol data through its packaged UI/runtime, and OAC only hosts the wrapper page plus trusted action bridge.
